# Research Terminal Implementation Goals

Status: product implementation goals  
Scope: future Tbot v1 web terminal evolution  
Created: 2026-06-01  
Implementation status: not implemented

## Purpose

Tbot should evolve toward a local research terminal for one private long-term
investor. The direction may be inspired by broad financial terminal products,
but every implementation must be native to this repository and constrained by
the Tbot ideology: sandbox-first, Russian-market focused, read-only research by
default, and no automatic broker actions from analysis.

This document records which terminal-style ideas are implementation goals and
which areas are explicitly out of scope.

## Product Boundary

The target terminal is:

- local and single-owner;
- focused on Russian-market instruments and related macro/factor context;
- backed by T-Invest, MOEX ISS, CBR, local SQLite, and owner-managed local data;
- implemented with Python 3.12, FastAPI, server-rendered Jinja2 templates, and
  existing service-layer patterns;
- educational and observational unless the owner manually uses the existing
  order flow.

The target terminal is not:

- an algorithmic trading platform;
- a signal bot;
- a crypto terminal;
- a prediction-market terminal;
- a multi-broker execution workstation;
- a quant/ML trading lab;
- an investment adviser.

## Transferable Goals

### G1 - DataHubLite Read-Only Data Layer

Goal: implement a Python-native topic/data layer for reusable Russian-market
data access.

Fit:

- maps directly to `docs/architecture/datahub_lite_ru_market.md`;
- centralizes T-Invest, MOEX ISS, CBR, local fundamentals, chart cache, and
  portfolio/watchlist read paths;
- returns typed payloads with `source`, `fetched_at`, `as_of_date`,
  `freshness`, `delay_status`, `ttl_seconds`, `data_gaps`, `errors`, and
  cache metadata.

Safety:

- read-only;
- no imports from order services, trading policy, Telegram order handlers,
  strategy modules, signal modules, ML modules, or LLM provider modules;
- no broker previews or broker orders.

### G2 - Equity Research Workspace

Goal: make ticker research feel like a focused terminal workspace.

Target sections:

- overview;
- issuer/company profile;
- instrument identity: ticker, FIGI, ISIN, lot size, board, exchange, currency;
- market snapshot with freshness and source labels;
- financial/fundamental data where available;
- dividends and corporate actions where available;
- sector and peer/competitor comparison;
- macro and index context;
- news/events;
- risk/data-quality notes and data gaps.

Safety:

- no runtime trading signals;
- no personal investment recommendations;
- no automatic order preview from research output.

### G3 - Portfolio Terminal Views

Goal: upgrade portfolio pages from a simple position table toward a quiet
terminal for long-term monitoring.

Target sections:

- total value and P/L summary;
- position table with weight in portfolio;
- source freshness for prices and valuation;
- exposure by sector, currency, tag, and factor;
- read-only performance history;
- local manual-order history context;
- data gaps and stale-data warnings.

Safety:

- portfolio analytics must remain observational;
- no optimizer-to-order flow;
- no auto-rebalance;
- no order button generated by analytics.

### G4 - Watchlist And Instrument Search

Goal: make watchlist management Russian-market aware.

Target capabilities:

- search by ticker/name using T-Invest and MOEX metadata;
- normalize ticker and board/classcode where practical;
- show FIGI, ISIN, lot size, currency, exchange, board, and data source;
- add portfolio tickers to watchlist;
- later connect watchlist rows to tags and factor notes.

Safety:

- adding to watchlist is local metadata management only;
- no trading signal or order action from watchlist membership.

### G5 - Factor Map / Relationship Map

Goal: adapt the relationship-map idea into an owner-managed factor terminal.

Target model:

- local tag dictionary;
- many tags per ticker;
- ticker-tag relationship notes;
- factor pages showing related portfolio positions and watchlist tickers;
- read-only links from tags to external or local data sources;
- exposure summaries by tag/factor.

Safety:

- factors are observation metadata, not signals;
- factor summaries must not create broker previews or orders.

### G6 - News And Event Monitor

Goal: add a read-only event monitoring workspace for long-term review.

Target capabilities:

- filter by ticker, sector, tag/factor, and source;
- store source, fetched time, article/event date, and data gaps;
- allow local notes or review flags later;
- show blocked/unavailable content as data gaps rather than inventing details.

Safety:

- no sentiment-to-order flow;
- no urgent trading prompts;
- no recommendation labels generated from news.

### G7 - Reports And Snapshots

Goal: generate local research snapshots that can be reviewed outside the app.

Target outputs:

- ticker snapshot;
- portfolio snapshot;
- factor/tag snapshot;
- data-source diagnostics snapshot.

Preferred first formats:

- HTML;
- Markdown.

Later formats may include PDF if the dependency and rendering cost are justified.

Safety:

- reports are educational and archival;
- reports must include source freshness and data gaps;
- reports must not contain hidden broker actions.

## Explicit Non-Goals

Do not implement or import:

- algorithmic trading;
- no-confirmation strategy execution;
- strategy builders;
- backtesting dashboards that imply live strategy deployment;
- auto-rebalancing;
- paper/live trading engines;
- crypto, wallets, DeFi, token pricing, or crypto exchanges;
- prediction markets;
- multi-broker execution frameworks;
- technical-signal dashboards;
- runtime BUY/SELL signals;
- AI quant labs, reinforcement learning trading, HFT, factor-discovery trading
  systems, or portfolio optimizers that produce actionable trades;
- LLM/agent systems that can call `OrderService.preview()` or
  `OrderService.execute()`.

## Implementation Order

Recommended order:

1. Implement DataHubLite schemas, topic parsing, TTL policy, and import-boundary
   tests.
2. Add read-only MOEX ISS and CBR adapters.
3. Add DataHubLite service orchestration and cache diagnostics.
4. Route existing research/charts through DataHubLite where this does not change
   public behavior.
5. Add `Ticker Tags` and `Tags` pages.
6. Add portfolio/watchlist tag and factor exposure views.
7. Add the richer Equity Research workspace.
8. Add read-only news/event monitoring.
9. Add HTML/Markdown snapshots.
