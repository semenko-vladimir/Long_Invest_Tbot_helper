# Tbot — помощник инвестора в Telegram

## О проекте

Tbot — личный учебный проект студента для портфолио. Это Telegram-бот на Python, в котором я учусь объединять внешние API, базу данных, фоновые задачи и понятный пользовательский интерфейс на примере инвестиционного помощника.

Идея проекта — собрать в одном чате информацию, за которой обычно приходится обращаться к нескольким источникам: состав портфеля, цены акций, дивиденды, графики и новости. Бот рассчитан на личное использование одним владельцем и поддерживает несколько его инвестиционных счетов. Данные счетов поступают через T-Invest, а рыночные данные — также через API Московской биржи (MOEX ISS). Локальная информация хранится в SQLite.

Это развивающийся учебный проект, а не готовый коммерческий сервис. Он не даёт персональных инвестиционных рекомендаций и не обещает доходность. Главная цель — показать, как я решаю практические задачи разработки и постепенно улучшаю приложение.

В боте можно просматривать портфель и позиции, вести список наблюдения, смотреть дивиденды и графики, а также получать уведомления о рыночных событиях и новостях. Мониторинг включается отдельно и работает только для выбранных пользователем настроек.

Основной сценарий покупки и продажи — ручной: бот показывает предварительный расчёт, а отправка заявки требует явного подтверждения. Режим по умолчанию — песочница, то есть тестовая среда брокера для проверки без реальных денег. Графики, уведомления и анализ новостей не создают брокерских заявок.

## Что уже умеет бот

- **Показывать портфель:** счета, позиции, стоимость и текущую нереализованную прибыль — изменение стоимости ещё не проданных бумаг.
- **Открывать карточки акций:** цена, данные позиции на выбранном счёте и графики за день, неделю или месяц.
- **Хранить заметки:** собственные тезисы пользователя по бумаге, доступные и после закрытия позиции.
- **Следить за выбранными акциями:** присылать обновления с заданным интервалом во время торгов.
- **Работать со списком наблюдения и дивидендами:** хранить интересующие инструменты и показывать доступные сведения.
- **Собирать новости и ежедневный обзор:** сохранять публикации, обрабатывать очередь и отправлять сводку при включённой подписке.
- **Использовать локальную языковую модель по желанию:** через Ollama получать краткие пояснения к новостям. Эта возможность отключена по умолчанию.
- **Проверять ручные заявки:** предварительно показать операцию и запросить подтверждение перед обращением к брокеру.

Например, пользователь открывает портфель, выбирает счёт и карточку `SBER`, смотрит график, сохраняет заметку и включает обновления раз в 30 минут. Подписка помогает наблюдать за позицией; решение о покупке или продаже пользователь принимает сам.

## Технологии и устройство проекта

| Технология | Для чего используется |
|---|---|
| Python 3.12 | Основной язык приложения |
| pyTelegramBotAPI | Команды, кнопки и сообщения в Telegram |
| T-Invest SDK | Данные брокерских счетов и ручные заявки |
| MOEX ISS, requests | Получение рыночных данных и публикаций |
| SQLite, SQLAlchemy | Локальное хранение данных и работа с ними из Python |
| Alembic | Изменение структуры базы при развитии проекта |
| APScheduler | Обновления и уведомления по расписанию |
| pandas, matplotlib | Обработка данных и построение графиков |
| Ollama, Qwen — опционально | Локальный разбор новостей |
| unittest | Автоматические проверки логики |

Код разделён по задачам: обработчики Telegram принимают команды, сервисы выполняют основную логику, интеграции обращаются к внешним источникам, а модели описывают данные в базе.

```text
app/
  run.py           — запуск бота
  client/          — Telegram-интерфейс, настройки и планировщики
  services/        — портфель, заявки, новости, заметки и слежение
  integrations/    — работа с внешними источниками данных
  backend/models/  — модели базы данных
  charts/          — данные и изображения графиков
alembic/           — миграции базы данных
tests/             — автоматические тесты
docs/              — инструкции и описание отдельных возможностей
deploy/            — файлы для серверного запуска
```

Текущий интерфейс проекта — Telegram. Ранее разрабатывавшийся веб-терминал на FastAPI вынесен в отдельный архив и не запускается вместе с ботом.

## Что проект показывает в портфолио

На этом проекте я практикую работу с API и сетевыми ошибками, проектирование базы данных, разделение кода на слои и тестирование бизнес-логики. Отдельные задачи — сохранять принадлежность данных конкретному счёту, избегать повторной обработки новостей и продолжать показывать последние доступные данные при сбоях источников.

В работе с локальной моделью я учусь проверять формат и допустимость её ответов: расчёты выполняет код, а модель используется для текстовых пояснений. Для брокерских операций предусмотрены отдельные проверки режима и подтверждения пользователя.

## Краткий гайд пользователя

### Установка и запуск

Нужны Python 3.12, токен Telegram-бота, Telegram chat ID владельца и токен песочницы T-Invest. Для необязательного разбора новостей понадобится отдельно установленная Ollama с локальной моделью.

Из корневой папки проекта создайте виртуальное окружение и установите зависимости:

```powershell
py -3.12 -m venv venv312
.\venv312\Scripts\python.exe -m pip install -r requirements-v1.txt
```

Создайте локальные файлы настроек:

```powershell
Copy-Item .env.example .env
Copy-Item users.example.json users.json
```

В `.env` укажите токен Telegram-бота (`BOT_TOKEN`). В `users.json` замените шаблонные Telegram chat ID и токен T-Invest для песочницы. Для начала оставьте `APP_MODE="sandbox"`, `ALLOW_PROD_TRADING="false"` и `SSL_TBANK_VERIFY="True"`. Не публикуйте эти файлы: в них находятся секреты.

Запустите бота:

```powershell
.\venv312\Scripts\python.exe app\run.py
```

Откройте чат с ботом и отправьте `/start`.

### Основные действия

- **Портфель и позиции** — просматривайте счета и состав портфеля.
- **Карточка акции** — нажмите тикер внутри счёта или отправьте `/stock SBER`: цена, прибыль позиции, график с индикаторами, заметки и слежение. При наличии акции на нескольких счетах бот предложит выбор.
- **Статистика** — `Stats` показывает текущий портфель и рынок; данные обновляются при открытии и каждые пять минут во время торгов. История локальных сделок доступна отдельно.
- **Заметки** — кнопка «Заметки» или `/notes SBER`: общий список для бумаги на всех ваших счетах, сохраняющийся после закрытия позиции.
- **Слежение за акцией** — в карточке выберите частоту от 5 до 1440 минут и период графика. Бот присылает текст и график во время биржевых торгов; доступны пауза и отключение. [Подробности](docs/stock-cards-and-tracking.md).
- **Список наблюдения** — добавляйте инструменты, за которыми хотите следить.
- **Дивиденды и графики** — проверяйте доступные сведения по инструментам.
- **Покупка и продажа** — выберите операцию, проверьте предварительный расчёт и подтвердите заявку вручную.
- **Мониторинг** — отправьте `/monitor`, чтобы настроить уведомления и ежедневную сводку. Например, `/monitor_alerts on` включает срочные уведомления, а `/monitor_digest on` — ежедневную сводку.

Мониторинг новостей и цен отключён, пока пользователь его не включит. Каждый час бот проверяет MOEX, ЦБ, РБК, Интерфакс и «Коммерсантъ», сохраняет публикации и оценивает их через отдельную очередь. Локальная Qwen включается параметром `NEWS_LLM_ENABLED=true`; настройки и лимиты перечислены в `.env.example`. Важные новости приходят сразу после разбора, остальные — в ежедневной сводке.

Ежедневный обзор содержит до трёх графиков интересных изменений цены и объёма по последней завершённой сессии, даже если ни одна акция не изменилась на 5%. Порог `/monitor_threshold` относится к срочным ценовым уведомлениям. `/digest_preview` показывает обзор из кэша без изменения отметки ежедневной доставки, а `/monitor` — состояние источников и очереди. При недоступности источника или модели сводка показывает доступные факты и отмечает ограничения. Подробнее — в [руководстве по ежедневному обзору](docs/hourly-news-and-daily-digest.md). Котировки MOEX могут поступать с задержкой; графики и разборы не размещают заявки.

Инструкции по переносу на Ubuntu, резервному копированию и запуску в фоне находятся в [руководстве по переносу](docs/ubuntu-transfer.md). Подробности о поддержке нескольких счетов описаны в [документе об архитектуре счетов](docs/multi_account_foundation.md).

## Планы развития

1. **Развивать работу с несколькими счетами.** Расширять учёт контекста конкретного счёта для стратегий, аналитики и уведомлений; не выбирать счёт по его названию или порядку в списке.
2. **Улучшать мониторинг рынка и новостей.** Развивать настройки источников и прозрачные правила отбора событий, сохраняя мониторинг отдельным от исполнения заявок.
3. **Проверять качество локального разбора новостей.** Сравнивать пояснения модели с исходными публикациями, улучшать проверки ответов и явно показывать ограничения. Расчёты портфеля должны оставаться проверяемой программной логикой, а вывод модели — не приводить к размещению заявок.
4. **Повышать надёжность локального и серверного запуска.** Улучшать инструкции по обновлению, резервному копированию баз и диагностике работы бота.

## Настройки безопасности

- Для локальной разработки используйте `APP_MODE="sandbox"`.
- Не отключайте проверку TLS: оставляйте `SSL_TBANK_VERIFY="True"`.
- Не добавляйте в Git `.env`, `users.json`, токены, локальные базы данных и резервные копии.
- Ручные заявки требуют явного подтверждения; автоматическая торговля не является целью проекта.

В коде также есть отдельный экспериментальный путь исполнения стратегий в песочнице. Он отключён по умолчанию, требует явного включения и лимитов и не используется для исполнения новостей или выводов модели. Автоматическое исполнение стратегий на реальном счёте заблокировано.

## Ограничения учебной версии

- Бот рассчитан на одного владельца с локальной конфигурацией, а не на публичный сервис с регистрацией пользователей.
- Котировки и новости зависят от доступности внешних источников; данные MOEX могут поступать с задержкой.
- Интерфейс пока содержит сообщения на русском и английском языках.
- Ответ языковой модели может содержать ошибки. Проверка структуры ответа не гарантирует правильность его смысла.
- Графики и индикаторы описывают данные, а не предсказывают будущую цену.

## Проверка проекта

Запуск тестов из корня репозитория:

```powershell
.\venv312\Scripts\python.exe -m unittest discover -q
```

В тестах проверяются, в частности, ограничения торговли, подтверждение заявок, разделение счетов, обработка новостей, графики, заметки и слежение. Эти проверки не заменяют ручную проверку интеграций в песочнице.
